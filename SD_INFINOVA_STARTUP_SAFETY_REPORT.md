## Startup flow and changes

The application has one production `initDatabase()` caller: `createApp()` in `server.ts`. Its order is:

1. `productionConfiguration()` validates required production variables, HTTPS origin/CORS relationship, absolute paths, and that both storage directories already exist (`server.ts:20-38`).
2. `initializeUploadsStorage()` runs (`server.ts:68-72`); in production this validates the pre-existing uploads directory and does not create it (`src/server/api.ts:21-30`).
3. `initDatabase()` runs (`server.ts:72`). A test child process also calls `initDatabase()` directly (`tests/security.test.ts` and `tests/storage-init.test.ts`), so the DB module now independently validates production configuration and authorization.

`src/server/db.ts` now checks the production PGlite path and requires `ALLOW_SCHEMA_MIGRATIONS=true` before constructing/opening PGlite (`:49-75`). On an empty production directory, it also validates initial administrator configuration before PGlite creates database files. After opening, it checks migration-ledger/admin state using catalog reads only (`:77-108`). It validates missing/legacy-admin bootstrap requirements before executing DDL. The `schema_migrations` table and schema version 001 are now created inside the same transaction (`:110-268`); ledger DDL no longer precedes the authorization check. The transactional DDL is rolled back on an error.

**Production configuration consequence:** keep `ALLOW_SCHEMA_MIGRATIONS=true` in the production secret/config store for normal startup. Its name is historical; it is now an explicit authorization required before every production PGlite open because schema state cannot be known safely without opening the directory. Setting it to anything else, including unset/false, fails closed before PGlite opens. Schema DDL is run only if version 001 is pending. `.env.example`, deployment, backup/restore, and fix-report guidance was updated to reflect this behavior.

Development remains supported without the production gate. Existing in-memory security tests pass. An isolated authorized production-style initialization and a subsequent restart without bootstrap variables both pass against a disposable temporary data directory.
