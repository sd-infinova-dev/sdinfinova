## A. Executive summary

**Overall verdict: NOT READY.** There are concrete launch blockers in administrator bootstrap credentials, request abuse protection, production database/storage assumptions, and client-only routing/SEO behavior. The production frontend bundle builds, but the type-check fails and the backend/runtime, database, forms, live domain, and hosting were not exercised.

**Highest risks:** a fixed administrator password is seeded on an empty database; inquiry submissions have no effective rate limit; administrative authorization does not enforce the user's role; SVG uploads and email HTML use untrusted content; PGlite and uploads depend on local disk; there is no backup/restore process; all SPA paths can return the same 200 HTML shell; the admin route has no `noindex` handling; build does not package or validate the backend runtime.

## C. Critical issues

1. **Default administrator password is embedded in source.** `src/server/db.ts:181-194` inserts an administrator with a fixed password whenever the database is empty. The password is hashed, but hashing does not make a known source credential safe. A fresh installation can be taken over. Remove the default and bootstrap only through an owner-controlled one-time secret or manual secure process; verify a clean isolated install has no usable default credential and that the bootstrap is consumed.
2. **Public inquiry submissions are not rate-limited.** The limiter is mounted only at `/api/v1/auth/login` (`server.ts:45-59,203-205`), while `/api/v1/inquiries` is public (`src/server/api.ts:258`). A bot can fill the database and trigger SMTP work. Add layered rate/abuse limits and test throttling safely in staging.
3. **Admin role is not enforced, only session existence.** `requireAdmin` fetches `role` but accepts any unexpired session (`src/server/api.ts:60-82`). Any future non-admin account would inherit full admin API access. Enforce role checks and test admin/non-admin direct requests.
4. **Production data/media durability and recovery are unproven and host-dependent.** Both database and uploads are local filesystem paths (`src/server/db.ts:6-32`; `src/server/api.ts:17-44`).
