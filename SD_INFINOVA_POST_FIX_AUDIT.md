## Summary of verified fixes

- No fixed administrator password is present in the reviewed bootstrap source; first-admin creation needs explicit environment credentials and legacy account rotation is gated.
- Session bearer material stays in HttpOnly cookies; the database stores a hash; expiry and logout invalidation are implemented.
- Protected admin handlers consistently use role-checking middleware; the editor-role denial is covered by the isolated suite.
- Unsafe protected API writes pass cookie/header CSRF validation, and hostile origins are rejected.
- Login/inquiry rate limits, server-side request schemas, body caps, email escaping, upload signature checks, SVG rejection, and private-note-safe logs are present.
- API/HTML unknown routes return 404s; admin path responses include `X-Robots-Tag`; public settings filter unknown private fields.
- Lint/type-check, isolated regression suite, and frontend production build all passed in this audit.
- `.env`, local DB, and upload runtime files are not tracked in the current index. This does not prove Git history is clean.

## Critical and high-risk issues still open

1. **High — production paths can be created before validation.** This defeats the “existing persistent volume” check and can allow a newly created local/ephemeral path to pass startup checks.
2. **High — lockfile is untracked.** Reproducible dependency installation is not established in the repository.
3. **High — essential production conditions are unverified.** Durable storage, backup/restore, migration against existing data, and legacy administrator rotation have not been exercised.
4. **High — crawler-visible content remains client-only.** There is no route-specific SSR/prerender or metadata; search/social rendering remains uncertain.
5. **High — staging and external controls are unknown.** Domain/TLS, proxy trust, production CSP/cookies, SMTP, persistent media, monitoring, and rollback remain unverified.

## External configuration and staging requirements

- Configure `NODE_ENV=production`, `PORT`, `PGLITE_DATA_DIR`, `UPLOADS_DIR`, HTTPS `PUBLIC_ORIGIN`, exact `CORS_WHITELIST`, and actual `TRUST_PROXY_HOPS` in the host configuration.
- Ensure the database and upload paths are pre-mounted durable storage, writable by the service, single-writer, backed up together, and not ephemeral.
- Provide `INITIAL_ADMIN_EMAIL` and a unique 16+ character `INITIAL_ADMIN_PASSWORD` only for initial creation/legacy rotation; remove them after successful rotation.
- Set `ALLOW_SCHEMA_MIGRATIONS=true` only for a planned deployment after backup and isolated restore; reset/remove immediately afterward.
- Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, and `NOTIFICATION_EMAIL` only if email notifications are enabled; validate in a provider sandbox.
- Optionally configure `GEMINI_API_KEY` if the feature is used. Never put secrets in Git or command history.
- Verify public DNS, HTTPS certificate/redirects, proxy forwarding, cookie flags, CORS preflight, CSP, health/readiness, inquiry delivery, valid upload persistence, restart/redeploy persistence, backup restore, monitoring/alerts, and rollback on authorized staging.
- Verify pricing, business claims, privacy/retention wording, routes, metadata, sitemap, and noindex behavior with the owner and browser/crawler checks.
